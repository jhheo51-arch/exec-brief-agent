# exec-brief-agent

재무표와 투자 가정 파일을 넣으면 임원이 한 장만 읽고 결정할 수 있는 보고서를 만든다.

## 왜 만들었나

임원 보고서에서 가장 자주 생기는 사고는 숫자가 틀리는 것이다. 문장을 고치다 숫자가 바뀌거나, 반올림 기준이 쪽마다 다르거나, 출처가 빠진다. 이 도구는 숫자와 문장을 나눠서 그 사고를 막는다.

## 규칙

1. 숫자는 전부 코드가 계산한다. 증감, 증감률, 영업이익률, NPV, 본전 현금흐름, 민감도 두 가지(할인율 2%p 상승, 현금흐름 10% 감소)를 만든다.
2. 계산한 숫자마다 F01 같은 ID와 출처를 붙인다.
3. 문장을 쓰는 쪽(규칙 기반 또는 Claude)은 숫자를 직접 쓰지 못하고 `{F03}`처럼 ID만 부른다.
4. 검사기가 통과시킨 보고서만 저장한다. 검사 항목은 다음과 같다.
   - 자리표시자 밖에 숫자가 있으면 실패
   - 근거는 정확히 3개
   - 선택지는 2개나 3개
   - 없는 ID나 중복 ID를 쓰면 실패
   - 확인할 가정은 입력 문장을 그대로 옮긴 경우에만 숫자 허용
5. 검사를 통과한 뒤 코드가 ID를 실제 값으로 바꾼다.
6. 결론, 근거 3개, 선택지와 조건, 확인할 가정, 결정 질문 순서로 쓴다. 결정은 사람이 한다.

## 사용법

```bash
pip install anthropic pytest
python -m brief --fin samples/financials.csv --inv samples/investment.json --out out/sample
```

`out/sample.html`(A4 가로 한 장), `out/sample.md`, `out/sample.json`이 생긴다.

### 두 가지 모드

| 모드 | 실행 | 설명 |
|---|---|---|
| 규칙 기반 | 기본값 | API 키 없이 돌아간다. 증감률이 큰 항목과 NPV를 근거로 고른다 |
| Claude | `--llm` | `ANTHROPIC_API_KEY`가 필요하다. 모델이 근거와 문장을 고르고, 검사에 걸리면 문제 목록을 받아 한 번 더 쓴다 |

두 모드 모두 같은 검사기와 같은 출력 화면을 쓴다.

## 입력 형식

- 재무표 CSV: `항목,당기,전기,단위,출처`
- 투자안 JSON: 이름, 출처, 초기투자, 연간현금흐름, 기간, 할인율, 단위, 확인할가정

`samples/`의 값은 모두 가상이다.

## 테스트

```bash
python -m pytest -q
```

숫자를 직접 쓴 문장, 없는 ID, 근거 개수 오류를 걸러 내는지 확인한다.

## 한계

- Claude 모드는 API 키가 있는 환경에서 아직 실행해 보지 않았다.
- 재무 항목 이름은 입력 CSV를 그대로 쓴다. 계정과목을 표준 이름으로 맞추는 기능은 없다.
